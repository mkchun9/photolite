
# PhotoLite — 프로젝트 개요서
---

## 1. 프로젝트 간단 소개

**PhotoLite**는 사진을 업로드하면 자동으로 용량을 최적화하고, 비슷한 사진을 중복으로 감지하며,
절약된 저장 용량을 통계로 보여주는 웹 서비스입니다.

- 업로드된 사진을 **WebP로 변환**하고 긴 변 기준으로 **Resize**하여 사진의 용량을 줄여줍니다.
- 지각 해시(average hash)로 **비슷한 사진을 중복으로 감지**하여 불필요한 중복 저장을 방지합니다.
- 갤러리에서 정리된 사진과 **총 절약 용량·절약률**을 한눈에 확인할 수 있습니다.

한 학기 동안 학습한 **클라우드 3-Tier 아키텍처**(프론트엔드 · 백엔드 · 데이터베이스)와 **AWS EC2 배포**,
**Docker** 컨테이너 운영을 직접 구현해 보았습니다.

---

## 2. 타겟 (주요 사용자)

- 사진이 너무 많아 휴대폰·클라우드 드라이브 **용량이 부족한 사용자**
- 블로그·쇼핑몰 등에서 **이미지 용량을 줄여 페이지 로딩을 개선**하려는 사이트 운영자
- 비슷한 사진이 쌓여 **중복 정리가 어렵고 번거로운 사용자**

---

## 3. 간단한 유저 시나리오

1. 사용자가 갤러리 화면에서 정리하고 싶은 **사진 여러 장을 업로드** 한다.
2. 시스템이 각 사진을 자동으로 **최적화(WebP·리사이즈)** 하고, 기존 사진과 비슷하면 **"중복"으로 표시** 한다.
3. 사용자는 **절약된 총 용량**과 정리된 **갤러리**를 한 화면에서 확인 가능하다.

---

## 4. 사용 기술 / 아키텍처

- **프론트엔드**: Next.js, shadcn/ui, React Query
- **백엔드**: NestJS(Node.js), sharp(이미지 처리)
- **데이터베이스**: PostgreSQL (사진 메타데이터)
- **인프라**: AWS EC2(Amazon Linux 2023), Docker Compose, nginx(리버스 프록시 + 이미지 정적 서빙)

```
[브라우저] ─:80─▶ [nginx] ─/ ─▶ [Next.js]
                       └─/api ─▶ [NestJS] ─▶ [PostgreSQL]
                       └─/storage ─▶ 최적화 이미지(EBS)
```

## 7. 한계 및 향후 과제 

- **중복 감지 정확도**: average hash 방식은 빠르고 가볍지만, 크게 편집된 사진은 놓치거나(누락) 서로 다른 사진을 비슷하다고 판단(오탐)할 수 있다. (더 정교한 해시(pHash) 또는 임계값 튜닝으로 개선 가능할 것)
- **원본 미보관**: 저장 용량을 줄이기 위해 최적화본만 보관하므로, 원본 보존이 필요하면 옵션을 추가해야 한다.
- **단일 인스턴스 / 로컬 스토리지**: EC2 한 대의 디스크에 저장합니다. (확장하려면 이미지 저장을 S3, 데이터베이스를 RDS로 분리하는 방향 고려)
- **중복 검사 방식**: 업로드마다 기존 항목과 전수 비교하게 된다. (사진이 매우 많아지면 해시 인덱싱 필요)
